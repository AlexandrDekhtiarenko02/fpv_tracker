# Пульт трекера

Всё, что нужно набирать руками. Команды сверены с этим репозиторием.

Где запускать: **[малина]** — в ssh на борту, **[мак]** — у себя,
**[sudo]** — спросит пароль, вводишь сам.

---

## Борт

Порядок всегда один: обновить → перезапустить → проверить. Пропуск последнего
шага — самая частая причина «я же обновил, а поведение прежнее».

**Обновить код** [малина]. Забирает код, дожидается записи на карту и
проверяет, что `tracker.py` цел. Обычный `git pull` не годится: карта пишет с
задержкой, и пропажа питания оставляет пустые файлы.

    cd ~/fpv_tracker && ./obnovit.sh

**Перезапустить службу** [малина] [sudo]. Без этого в памяти остаётся прежний
код, сколько ни обновляй файлы.

    sudo systemctl restart tracker && sleep 8 && ~/fpv_tracker/status.sh

**Что сейчас летит** [малина]. Сверяет запущенный процесс с репозиторием по
md5. Нужно увидеть СОВПАДАЕТ и правильный коммит.

    ~/fpv_tracker/status.sh

**Остановить трекер** [малина] [sudo]. Нужно, когда порт полётника занимают
инструменты — второго клиента MSP плата не примет.

    sudo systemctl stop tracker
    # ... поработали инструментом ...
    sudo systemctl start tracker

## Логи

Один заход — одна папка в `flight_logs/zahvaty/`. В имени стоит коммит,
которым он снят, так что версию видно прямо в списке.

**Последние заходы** [малина]:

    ls -dt ~/fpv_tracker/flight_logs/zahvaty/*/ | head -10

**Разбор одного захода** [малина]:

    cat "$(ls -dt ~/fpv_tracker/flight_logs/zahvaty/*/ | head -1)/итог.txt"

**Забрать логи к себе** [мак]. Запускается из любого места — скрипт сам
переходит к себе в каталог. Без аргумента кладёт в `flight_logs/` рядом с
собой, с аргументом — куда скажешь.

    ~/Desktop/fpv_tracker/fetch_logs.sh
    ~/Desktop/fpv_tracker/fetch_logs.sh ~/Desktop/Logs

Если имя борта не резолвится, адрес задаётся отдельно:

    PI=192.168.1.50 ~/Desktop/fpv_tracker/fetch_logs.sh ~/Desktop/Logs

**Посмотреть, что уйдёт при чистке** [малина]. Ничего не удаляет:

    cd ~/fpv_tracker && ./clean_logs.sh

**Стереть логи** [малина]. НЕОБРАТИМО. Удаляет полётные csv, журналы, папки
захватов и снимки. Сохраняет записи кадров (`recordings/`) и разборы
(`rendered/`). Перед стиранием забери то, что понадобится для разбора.

    cd ~/fpv_tracker && ./clean_logs.sh --yes

## Диагностика

Порядок поиска причины: сбои кадра → журнал вылета → журнал службы.

> **Признак, который легко пропустить:** служба крутится в цикле
> перезапусков, а в журнале ни одной ошибки. Это порча файла — пустой
> `tracker.py` Python выполняет молча и сразу выходит, systemd видит чистый
> выход и поднимает заново. Лечится в разделе «Аварии».

**Сбои в обработке кадра** [малина]. Первое, куда смотреть, если пропал
оверлей, не берётся захват или борт ведёт себя странно:

    journalctl -u tracker -n 300 --no-pager | grep "СБОЙ В ОБРАБОТКЕ" | tail -3

**Журнал последнего вылета** [малина]:

    tail -40 "$(ls -t ~/fpv_tracker/flight_logs/*.events.log | head -1)"

**Служба целиком** [малина]:

    systemctl status tracker --no-pager -n 20

**Знаки осей** [малина] [sudo]. ВИНТЫ СНЯТЬ. Обязательно после смены
полётника или перестановки моторов: «стандартное» соглашение на этом борту
однажды уже не совпало.

    sudo systemctl stop tracker
    python3 ~/fpv_tracker/tools/os_znaki.py
    sudo systemctl start tracker

**Барометр** [малина] [sudo]. Сравнивает все источники высоты сразу:

    sudo systemctl stop tracker
    python3 ~/fpv_tracker/tools/baro_probe.py
    sudo systemctl start tracker

**Сравнить версии по рывкам** [малина]. Главный инструмент разбора контура:
показывает распределение скачков команды по коммитам. Смотреть ХВОСТ (90-й,
99-й процентиль, максимум), а не медиану — пилот чувствует редкие крупные
рывки, а не среднее.

    python3 ~/fpv_tracker/tools/sravnit_versii.py           # тангаж
    python3 ~/fpv_tracker/tools/sravnit_versii.py cmd_roll  # крен

**Вердикты последних заходов** [малина]. Чем кончился каждый: срыв слежения,
перелёт, недолёт, не сблизились или сошлось.

    for d in $(ls -dt ~/fpv_tracker/flight_logs/zahvaty/*/ | head -8); do grep -A1 "ЧЕМ КОНЧИЛОСЬ" "$d/итог.txt" | tail -1; done

**Прогнать проверки** [мак]. Работает и на борту:

    cd ~/Desktop/fpv_tracker && ./run_tests.sh

## Настройки борта

Файл `local_settings.py` лежит вне репозитория: `git pull` его не трогает.
Любая величина из `tracker.py` переопределяется дописыванием строки.

**Посмотреть текущие** [малина]:

    grep -v '^#' ~/fpv_tracker/local_settings.py | grep -v '^$'

**Изменить величину** [малина]. Если имя набрано с опечаткой, трекер
напечатает при старте «неизвестное имя — пропущено»:

    echo 'P_GAIN_PITCH = 1.4' >> ~/fpv_tracker/local_settings.py
    sudo systemctl restart tracker

Что чаще всего крутится:

| Величина | Что делает | Куда двигать |
|---|---|---|
| `OBSERVE_ONLY` | Трекер смотрит и пишет, но не рулит | `True` — сбор данных, `False` — управление |
| `P_GAIN_PITCH` | Резкость доворота по тангажу | Раскачивает — вниз |
| `PITCH_RATE_DAMP` | Гашение колебаний по гироскопу | Раскачивает — вверх, но ниже 0.7 |
| `MAX_PITCH_DEFLECT` | Предел отклонения оси | Крутит через нос — вниз |
| `FINAL_HOLD_ROST` | Во сколько раз рамка вырастет до заморозки команды | Замирает рано — вверх |
| `ACQ_SNAP_RADIUS_MAIN` | Радиус зоны поиска при захвате | Мажешь мимо — вверх |
| `ACQ_SNAP_YADRO_MIN_ABS` | Насколько цепко прицел держит своё место | Перекидывает — вниз |
| `RECORD_FRAMES` | Запись кадров с камеры | Стоит кадров — `False` |

Откатить всё разом — удалить дописанные строки. Величины вернутся к тем, что
в `tracker.py`, а там у каждой записано, откуда взялось её значение.

## Аварии

Одна беда даёт себя знать чаще прочих: пропажа питания на ходу. Карта пишет с
задержкой, и в окне между «имя файла на диске» и «содержимое на диске» всё
обрывается.

**Починить репозиторий** [малина]. Настройки борта и логи лежат вне git — их
не тронет:

    cd ~/fpv_tracker && ./pochinit.sh

**Проверить целость вручную** [малина]. Пусто в выводе — всё хорошо:

    cd ~/fpv_tracker
    find . -maxdepth 2 -type f -size 0 -not -path './.git/*' -not -path './flight_logs/*'
    find .git/objects -type f -size 0
    git fsck --no-progress

**Найти малину в сети** [мак]:

    cd ~/Desktop/fpv_tracker && ./find_pi.sh

**Отправить код без git** [мак]. Запасной путь, когда борт в сети, а GitHub
недоступен:

    cd ~/Desktop/fpv_tracker && ./deploy.sh
